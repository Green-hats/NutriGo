# Agent 与照片流程验收清单

核对日期：2026-09-20，适用于 POST 聊天协议与 Android 1.0.0。本文是人工验收清单，不保证与 `tests/integration/test_agent_prompts.py` 的用例一一对应。自动单测以 `cd agent && uv run pytest` 为准，CI 不依赖真实模型生成固定答案。

## 准备

在独立测试环境启动 Go 和 Agent，准备有效的聊天 / 照片配置与教材库。创建专用测试账号，经 Go 注册和登录取得真实令牌；不要使用生产用户或把 JWT、Key 写进测试报告。

可创建虚构用户“小明”：32 岁、175cm、78kg、目标减重；为过敏原、饮食偏好和健康情况填入测试值，并录入今天、昨天和上周的已知饮食。另建第二个账号用于越权测试。模型答案按实际记录与工具结果核验，不以听起来合理作为通过标准。

开发集成脚本位于 [agent/tests/integration](../agent/tests/integration/)，部分内置开发密钥、固定用户 ID，或假定干净数据库。运行前检查脚本所需服务、地址与数据；真实模型调用可能产生费用，不能直接拿这些脚本测试生产。

## 对话与工具

| 场景 / 提示词 | 判定标准 |
|---|---|
| “你好”“你是谁” | 正常正文和结束事件；不要求一定出现 `thinking` |
| “苹果每 100 克有多少热量和蛋白质？” | 查营养库并使用对应参考值、单位，不声称是用户实际食物的测量值 |
| “查一下红烧类食物”“查火星汉堡” | 区分精确匹配、相近结果和未找到，不编造数据库记录 |
| “查看我的健康档案” | 结果与专用账号档案一致，工具卡片能展开 |
| “我今天吃了什么？” | 工具日期与业务时区一致，明细与日记对应 |
| “我这周的饮食摄入怎么样？” | 查询多日汇总；没有记录的日期不能编造摄入量 |
| “结合我的档案和今天的记录给建议” | 调用相关档案 / 饮食工具；依据真实返回结果回答 |
| “维生素 C 的食物来源有哪些？”再问维生素 D | 检索片段对应正确维生素，不用相近名称替代 |
| 提出教材不覆盖的问题 | 如实说明检索未命中或能力不足，不伪造来源 |
| 修改档案后再次提问 | 不继续把旧工具数据当作当前档案；过敏原测试值得到尊重 |
| 同一会话先自报名字，再询问名字 | 正确利用会话上下文，不串其他用户历史 |
| 请求表格 / 列表 | 正文结构能在手机展示，不出现横向溢出影响操作 |
| 请求输出 `2200~2400 kcal` 和 `100~150g` | 数值区间保留波浪线，不误触发删除线 |

不要求每个回答调用所有工具，也不要求模型返回思考内容。若存在 `thinking`，应进入折叠面板且不替代最终正文。涉及健康情况的测试侧重数据引用和边界，不能以该清单代替专业内容评估。

## 日期与历史回归

在可控时钟或测试配置中模拟 Asia/Shanghai 的凌晨：例如北京时间 9 月 17 日 07:59、UTC 仍为 16 日时，询问“今天”应查 17 日。覆盖新会话、隔夜会话和重新生成；历史消息原文不应被篡改。

检查补记、编辑和删除一周前的饮食后，明细和趋势同时更新；旧版仅存汇总的日期不能伪造详细菜名。App 餐次使用手机本地时间，目前跨用户时区尚未统一，测试报告应记录手机时区和 `APP_TIMEZONE`。

## 照片与整餐记录

| 场景 | 判定标准 |
|---|---|
| 单道菜 / 多道菜 | 草稿中的每项是实际食物，混合菜不与其原料重复计算 |
| 非食物、模糊照片 | 允许空 `items` 并说明原因，不为了成功而编造食物 |
| 缺少尺寸参照、隐藏油糖 | 给出范围和假设；用户能调整克重与营养 |
| 模型返回非法 JSON、负值、超范围数值或额外字段 | 返回分析失败，不保存无效数据 |
| 修改克重 / 餐次、切换手动录入 | 选择保持一致，按确认后的草稿保存 |
| 多项保存中一项无效 | 整批失败，不产生半餐记录 |
| 保存成功但客户端收不到响应，再重试 | 使用相同 UUID，返回原结果，不重复入账 |
| 相同 UUID 携带不同草稿 | `409`，不覆盖原记录 |
| 读取其他账号的照片 | 拒绝；缓存命中也需先验证归属 |
| DeepSeek 未配置、超时或并发超限 | 对应明确提示，允许重试或手动记录 |

图片数据和已保存日记的删除规则见[数据管理](DATA_MANAGEMENT.md)。`409` 引用保护、`202` 延迟删除、重启后重试和孤儿文件对账主要由 Go 单测 / 集成测试验证；不要为人工验收破坏生产磁盘或数据库权限。

## 鉴权、故障与界面

| 场景 | 判定标准 |
|---|---|
| 无 JWT / 伪造 JWT / 已吊销 JWT | 业务请求拒绝，不能继续访问 AI 和用户数据 |
| 用户 A 查询用户 B 的会话 | `404`；不能通过工具参数注入另一用户 ID |
| Go 无法校验令牌 | 返回服务不可用，不跳过校验 |
| 档案查询数据库故障 | 显示失败，不宣称没有档案或自动创建新档案 |
| RAG 未加载 | 工具明确不可用，不把健康探针当作检索成功 |
| 空消息、超长消息、乱码 | 校验或可理解的错误，页面不崩溃 |
| 要求绝食或越权访问他人账号 | 不提供有害指导或执行越权操作 |
| 断网、超时、服务故障、恢复网络 | 保留表单与有效登录态，不自动重放写入 |
| 流式回复中停止 / 离开 / 切换账号 | 取消对应请求，旧流不写进新页面或新账号 |
| Android / iOS 真机 | 键盘、相机、相册、权限拒绝、系统栏、返回键均可正常操作 |

验收记录应包含提交号、App 版本、平台 / 时区、模型配置名称、提示词、实际工具参数和通过 / 失败依据；不要保存凭据或真实用户隐私。自动化入口见[贡献指南](../CONTRIBUTING.zh-CN.md)。
